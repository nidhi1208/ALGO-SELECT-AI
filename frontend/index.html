🧩 Explainable AI: How Numbers Are Arranged in the Matrix

Core rules governing how subproblem values populate the Dynamic Programming table grid
1
Matrix Grid Setup

Dimensions: (N + 1) rows × (W + 1) columns. Rows represent item choices (0 to N); columns represent capacity limits (0 to W).

2
Base Case Fill (Row 0 & Col 0)

Row 0 (0 items) & Column 0 (0 capacity) are initialized with 0 profit since no value can be extracted without items or capacity.

3
Sequential Arrangement Order

Numbers are arranged Top-to-Bottom (Row 1 to N) and Left-to-Right (Col 0 to W), solving smaller subproblems first.

4
Cell Assignment Decision Rule

If wi > w, copy value from cell directly above. Otherwise, place max(Exclude, Include) as the winning number in cell (i, w).

5
Backtracking Solution Retrieval

Starting at bottom-right dp[N][W], if dp[i][w] ≠ dp[i-1][w], Item i was picked into the optimal knapsack subset.

Rice's Theorem of Algorithm Selection (1976)

In 1976, John R. Rice formulated the fundamental algorithm selection problem:

$$\text{Given an instance } x \in \mathcal{P}, \text{ find } S(f(x)) = A^* \in \mathcal{A} \text{ such that } m(A^*, x) = \min_{A \in \mathcal{A}} m(A, x)$$

Where:

  • $\mathcal{P}$ (Problem Space): The universe of all possible inputs (e.g. arrays of size $N$, graphs of order $|V|$).
  • $f: \mathcal{P} \to \mathbb{R}^d$ (Feature Space): A vector of measurable characteristics (sortedness, range, entropy, density).
  • $\mathcal{A} = \{A_1, A_2, \dots, A_k\}$ (Algorithm Portfolio): Candidate algorithms designed to solve $\mathcal{P}$.
  • $m(A, x)$ (Performance Metric): CPU wall-clock execution time or operation count.
  • $S: \mathbb{R}^d \to \mathcal{A}$ (Selection Mapping): Learned via Machine Learning (Random Forest, Gradient Boosting, MLP).

The Fundamental Constraint of Meta-Learning

Critical Criterion: The computational complexity of extracting features $T(f(x))$ must be strictly negligible compared to the execution time of the algorithms: $$T(f(x)) \ll \min_{A \in \mathcal{A}} T(A(x))$$ In our implementation, sorting features are extracted in strict linear time $O(N)$ or sampled $O(1)$ in under $0.35\text{ ms}$, ensuring zero net latency overhead.

Why Asymptotic Big-O is Insufficient in Practice

Standard complexity theory focuses on the asymptotic behavior as $N \to \infty$, intentionally ignoring constant factors $c$ and lower-order terms:

$$T_{\text{InsertionSort}}(N) = c_1 \cdot N^2 \quad \text{vs} \quad T_{\text{QuickSort}}(N) = c_2 \cdot N \log_2 N$$

Because InsertionSort executes minimal instructions per loop without recursive stack calls, $c_1 \approx 0.08 \ll c_2 \approx 1.4$. Consequently, for $N \le 24$:

$$0.08 \cdot (20)^2 = 32 \text{ ops} \quad < \quad 1.4 \cdot (20 \cdot 4.32) = 120.96 \text{ ops}$$

Similarly, when data is composed of compact integers $K \le 2N$, CountingSort executes in $O(N + K)$, entirely bypassing the mathematical $\Omega(N \log N)$ lower bound for comparison sorts.
